# Review, discovery, and wider improvement

Read only for a motion review, an explicit search for useful animation, or a scoped audit/improvement task. Preserve the caller's mode: a review or discovery request returns findings; an implementation task already authorized continues through fixes and verification. Do not add a new compulsory selection pause or a second coordinator.

## Select the question

- **Review existing motion:** inspect the intended behavior and actual implementation. Trace entry/exit, pacing, origin, interruption, focus, reduced motion, pointer behavior, and effects on content. Separate an observable defect from a design preference and a performance hypothesis. Confirm source findings in the real journey when possible.
- **Find opportunities:** start from user intent and frequency; consider missing feedback, broken spatial continuity, or abrupt state changes. Propose motion only when it helps. Preserve instant repeated work. Accept no worthwhile addition, and do not invent rejected ideas or a minimum number of effects to fill a format.
- **Wider improvement:** inventory the affected surfaces and existing tokens/drivers, then rank concrete fixes by user impact, confidence, risk and dependencies. Reuse the existing task plan; do not require one plan file per cosmetic finding or run another supervisor.

## Make findings executable

For each material finding, give the trigger, actual behavior, expected behavior, source location, consequence, and evidence or uncertainty. A Before/After/Why table is useful when it clarifies several code changes; it is not a universal output requirement or a substitute for evidence. Do not block on personal curve or timing preferences unless a real requirement or defect supports it.

For substantial delegated remediation, provide the source artifact, affected paths, current-code evidence, intended behavior, relevant repository exemplar/tokens, boundaries, and observable acceptance criteria. Small fixes need only the relevant details. Implementation, PR follow-through, merge, deployment, and external messages retain their existing authorization.

Use slowed playback or frame inspection to explain coordination defects, then exercise normal-speed interaction. Check repeated activation, reversal, exit/unmount, keyboard focus, reduced motion and relevant input capabilities. Report missing runtime/device access as unverified. Use [break-ui](../../break-ui/SKILL.md) for data/layout stress, not to imply that a motion review tested every content state.

[Shared verification](../SKILL.md#verify-the-interaction) owns completion; [motion construction](motion.md) and [performance](performance.md) are optional details for the identified mechanism.
